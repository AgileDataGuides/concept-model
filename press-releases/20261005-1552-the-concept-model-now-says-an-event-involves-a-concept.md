# The Concept Model Now Says an Event Involves a Concept, Like the Business Event Matrix

**5 October 2026**

AgileDataGuides today changed the Concept Model app to say that a Core Business Event involves a Concept, the word the Business Event Matrix app already uses, so the two apps describe the same idea the same way.

## The Problem

The Concept Model app said an Event "joins" a Concept. Step 8 listed each Event's Joins, the Definitions tab read "Joins Customer, Subscription", and the Excel export had a Joins column. To a data team, a join is something done to two tables, so the word pointed at the wrong idea. The Business Event Matrix app already said an Event involves a Concept, so a team moving between the two apps met two words for one idea.

## The Solution

The app now says involves wherever it shows an Event and its Concepts. Step 8 lists the Concepts each Event **Involves**, and you add one with **Add a Concept**. The Definitions tab reads "Involves Customer, Subscription", and the Excel export's column is Involves. The new Event Matrix tab marks a cell with a check (✓) when the Event involves the Concept, as the Business Event Matrix app does. The Relationship steps now say a verb connects two Concepts.

## Key Benefits

- **One word for one idea**: an Event involves a Concept, in every tab, in the Excel export and in the Business Event Matrix app
- **No false hint of a table join**: the words describe the organisation, not a database
- **Nothing to convert**: only the words changed, and saved models load as before

The new wording is available now in the Concept Model app in the Context Plane monorepo, and it reaches the public app at [github.com/AgileDataGuides/concept-model](https://github.com/AgileDataGuides/concept-model) and its [live demo](https://agiledataguides.github.io/concept-model/) on its next publish.
